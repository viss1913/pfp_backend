# Матрица инфляции по месяцам (предложение)

## Формат матрицы (по месяцам горизонта)

Инфляция задаётся **по диапазонам месяцев от старта**. В настройках вводится **годовая** ставка (%), для расчётов переводится в месячную.

**Диапазоны создаёт агент** — в системе нет дефолтной матрицы и нет зашитых значений. Агент при настройке проекта задаёт список диапазонов (от месяца до месяца + годовая %).

Пример (только для иллюстрации формата):

| Месяцы | Годовая % |
|--------|-----------|
| от 0 до 12 (не включая 12) | 7,5 |
| от 12 (вкл.) до 24 (не вкл.) | 6,7 |
| от 24 (вкл.) до 48 (не вкл.) | 6,0 |

**Хранение** — настройка в `system_settings`, например `inflation_rate_matrix` (JSON). Структура целиком на стороне агента:

```json
{
  "ranges": [
    { "fromMonth": 0, "toMonthExcl": 12, "rateAnnual": 7.5 },
    { "fromMonth": 12, "toMonthExcl": 24, "rateAnnual": 6.7 },
    { "fromMonth": 24, "toMonthExcl": 48, "rateAnnual": 6.0 }
  ]
}
```

**Без поля по умолчанию.** Для месяца `m` (0-based): ищем диапазон где `fromMonth <= m < toMonthExcl`. Если месяц попадает вне всех диапазонов (например m ≥ 48 при таких ranges) — берём ставку **последнего** диапазона (продлеваем последний диапазон на весь оставшийся горизонт). Все значения `rateAnnual` — **годовые проценты**.

---

## Годовая vs месячная в коде (важно)

В настройках и в API везде **годовая** инфляция (%). В расчётах в части мест используется **месячная** (доля за месяц). Переводить нужно **степенным** способом, иначе будет рассинхрон с годовыми формулами.

**Правильный перевод годовая → месячная:**

- Годовая: `r` (% в год). За год множитель: `(1 + r/100)`.
- Месячная (доля за 1 месяц): множитель за месяц должен дать за 12 месяцев ровно `(1 + r/100)`, значит  
  **месячная доля** = `(1 + r/100)^(1/12) - 1`.

В коде уже есть правильная формула в `BaseCalculator.getMonthlyInflation(annualPercent)`:

```js
getMonthlyInflation(annualInflationPercent) {
    return Math.pow(1 + (annualInflationPercent / 100), 1 / 12) - 1;
}
```

**Неправильно** (линейное деление): `(r/12)/100` — так в части мест сделано (см. ниже), даёт другой эффект за год и не совпадает с годовыми множителями.

## Где что используется (обзор по коду)

### Годовая инфляция (множитель за несколько лет/месяцев)

| Файл | Как используется |
|------|------------------|
| **calculationService** (госпенсия) | `(1 + r/100)^yearsToPension` — индексация стоимости балла и фикс. выплаты |
| **PensionCalculator** (calculateStatePension) | то же: годовая на весь срок |
| **PensionCalculator** (calculate) | desiredPensionMonthlyFuture = target × (1 + r/100)^years_to_pension — **годовая** ок |
| **PassiveIncomeCalculator** | desiredIncomeFuture = … × (1 + inflationRate/100)^termYears — **годовая** ок |
| **OtherGoalCalculator** | targetAmountFuture = target × (1 + **inflationMonthly**)^termMonths — по сути эквивалент годовой через месячную (корректно, т.к. getMonthlyInflation используется) |

### Месячная инфляция (цикл по месяцам, рост пополнения)

| Файл | Как используется | Проблема |
|------|------------------|----------|
| **BaseCalculator.getGoalInflows** | `r *= (1 + inflationMonthly)` по месяцам — пополнение растёт по инфляции | Параметр одна ставка; с матрицей нужна ставка по месяцу `m` |
| **BaseCalculator.runSimulation** | `indexationRate` в `indexedReplenishment = monthlyReplenishment * (1 + indexationRate)^(m-1)` | В пенсии туда передают инфляцию; в Other/Passive — `investment_expense_growth_monthly` (другая настройка) |
| **PensionCalculator** | `infl_month_decimal = (inflationAnnualUsed/12)/100` и передаётся как indexationRate | **Линейное деление** — надо заменить на getMonthlyInflation(annual) |
| **PassiveIncomeCalculator** | `infl_month_decimal = (inflationRate/12)/100` (переменная есть, для desiredIncomeFuture используют годовую — ок) | Линейное деление нигде в коде дальше для инфляции не вижу в пассивном доходе для indexation — там investment_expense_growth_monthly |

Итого по переводу:

- Везде, где из **годовой** получают «месячную» для пошаговых расчётов, использовать **только** `getMonthlyInflation(annualPercent)` (степень 1/12), не делить год на 12 линейно.
- С матрицей: для месяца `m` брать `rateAnnual = getInflationRateForMonth(matrix, m)`, затем `monthlyRate = getMonthlyInflation(rateAnnual)`.

## Расчёты с матрицей по месяцам

### 1. Ставка для месяца m (0-based)

```text
getInflationRateForMonth(matrix, m):
  для каждого range in matrix.ranges (порядок важен):
    если range.fromMonth <= m < range.toMonthExcl → return range.rateAnnual
  если ranges не пустой → return ranges[последний].rateAnnual   // продлеваем последний диапазон
  иначе → fallback на inflation_rate_year (одна ставка на весь горизонт)
```

### 2. Множитель на N месяцев (для целевой суммы в будущем и т.п.)

Годовая в настройках → для каждого месяца своя месячная ставка, множитель = произведение по месяцам:

```text
mult = 1
for m = 0 .. N-1:
  r_annual = getInflationRateForMonth(matrix, m)
  r_month = (1 + r_annual/100)^(1/12) - 1
  mult *= (1 + r_month)
return mult
```

Эквивалент: `mult = ∏ (1 + getMonthlyInflation(getInflationRateForMonth(matrix, m)))` для m = 0..N-1.

### 3. Множитель на N полных лет (пенсия: стоимость балла, фикс. выплата)

Можно считать как множитель за N*12 месяцев по пункту 2. Либо отдельной функцией «по годам»: для года `y` (0-based) все 12 месяцев с одной ставкой из диапазона (месяцы 12y .. 12y+11). Для консистентности с «по месяцам» лучше считать по месяцам: годы тогда получаются автоматически.

### 4. Симуляция по месяцам (getGoalInflows, runSimulation)

- В цикле по месяцу `m` (1-based в части кода — уточнить и унифицировать): взять `monthIndex = m - 1` для 0-based.
- `rateAnnual = getInflationRateForMonth(matrix, monthIndex)`.
- `inflationMonthly = getMonthlyInflation(rateAnnual)`.
- Дальше как сейчас: пополнение умножать на `(1 + inflationMonthly)` и т.д.

## Проверка математики (чтобы не лохануться)

### Перевод годовая → месячная

- Годовая ставка `r` (%): за 12 месяцев сумма должна вырасти в `(1 + r/100)` раз.
- Значит множитель за 1 месяц: `(1 + r/100)^(1/12)`.
- Месячная **доля** (для формулы вида `сумма *= (1 + доля)`):  
  `monthlyRate = (1 + r/100)^(1/12) - 1`.

Проверка: если 12 месяцев подряд умножать на `(1 + monthlyRate)`, получится  
`(1 + monthlyRate)^12 = (1 + r/100)` — ок.

Линейное деление `r/12` в процентах дало бы за год множитель `(1 + r/1200)^12`, что при r=4 даёт ~1.0407 вместо 1.04 — мелкая ошибка, но для консистентности везде степенная формула.

### Множитель инфляции за N месяцев (разные ставки по месяцам)

Цель: сумма сегодня `S`, через N месяцев в «будущих ценах» должна быть  
`S * mult`, где `mult` — накопленная инфляция.

По месяцам (0-based): месяц 0 — ставка r₀, месяц 1 — r₁, …  
Множитель за месяц k: `(1 + r_k/100)^(1/12)`.  
Множитель за N месяцев:

```
mult = ∏_{k=0}^{N-1} (1 + r_k/100)^(1/12)
```

Это и есть формула из раздела «Множитель на N месяцев»: для каждого месяца берём годовую ставку из матрицы, переводим в месячную, перемножаем. Математически корректно.

Проверка при одной ставке r для всех месяцев:  
`mult = (1 + r/100)^(N/12)` — совпадает с текущей логикой «одна годовая на весь срок».

### Рост пополнения по месяцам (getGoalInflows, runSimulation)

Сейчас (одна ставка): в месяц m (1-based) пополнение = `replenishment * (1 + inflationMonthly)^(m-1)`.

С матрицей: в месяц m пополнение должно быть  
`replenishment * ∏_{i=0}^{m-2} (1 + monthlyRate(i))`,  
где `monthlyRate(i)` — месячная инфляция для месяца с индексом i (0-based). То есть каждый месяц своя ставка из матрицы, переведённая в месячную, и накопленное произведение — ок, в документе так и описано.

### Граничные случаи

- **N = 0 месяцев**: множитель = 1 (произведение по пустому множеству).
- **Месяц m вне диапазонов**: берём ставку последнего диапазона (продление) — поведение задано.
- **Пустая матрица**: fallback на одну ставку `inflation_rate_year` — тогда все формулы сводятся к текущей одной ставке.

Итого: с расчётами всё ок, если хелперы реализовать по описанным формулам и везде месячную получать через `getMonthlyInflation(annual)`.

## Обратная совместимость

- Если настройки `inflation_rate_matrix` нет или она пустая (ranges отсутствует/пустой) — везде использовать одну ставку `inflation_rate_year` (как сейчас): и для «ставка за месяц m», и для множителя за N месяцев. Дефолтной матрицы в коде не зашиваем — матрицу создаёт агент.
- У целей по-прежнему может быть своя `goal.inflation_rate` (годовая) — как override одной ставки при отсутствии/игнорировании матрицы для этой цели; детали на усмотрение.

## Где менять в коде (кратко)

| Место | Что сделать |
|-------|--------------|
| **Расширение настроек** | Читать `inflation_rate_matrix` (JSON), отдавать в контекст расчётов; fallback на `inflation_rate_year`. |
| **Хелперы** | Реализовать `getInflationRateForMonth(matrix, monthIndex)` и `getInflationMultiplierForMonths(matrix, monthsCount)` (и при необходимости обёртку за N лет). Везде переводить годовую → месячную только через `getMonthlyInflation(annual)`. |
| **calculationService / PensionCalculator (госпенсия)** | Множитель за yearsToPension лет = множитель за 12*yearsToPension месяцев по матрице. |
| **PensionCalculator (цель пенсии)** | desiredPensionMonthlyFuture и indexationRate: множитель за monthsToPension по матрице; indexationRate по месяцам — не одна величина, а получать ставку за месяц m через матрицу и getMonthlyInflation. |
| **OtherGoalCalculator** | targetAmountFuture = target × getInflationMultiplierForMonths(matrix, termMonths). В getGoalInflows передавать не одну inflationMonthly, а функцию/объект «инфляция по месяцу» или контекст с матрицей. |
| **PassiveIncomeCalculator** | desiredIncomeFuture через множитель за termMonths по матрице. |
| **InvestmentCalculator** | Если там используется инфляция — по той же схеме. |
| **BaseCalculator.getGoalInflows** | Принимать матрицу (или контекст с матрицей) и для каждого месяца m брать getInflationRateForMonth + getMonthlyInflation. |
| **BaseCalculator.runSimulation** | Где передаётся indexationRate из инфляции (пенсия) — по месяцам подставлять месячную инфляцию из матрицы. |
| **Исправление бага** | В PensionCalculator заменить `(inflationAnnualUsed/12)/100` на `getMonthlyInflation(inflationAnnualUsed)` везде, где эта «месячная» используется как инфляция. |

## Итог

1. Матрица по **месяцам** горизонта: **диапазоны создаёт агент**, в системе нет дефолтной матрицы и нет поля «по умолчанию». Для месяцев вне заданных диапазонов — продлеваем ставку последнего диапазона.
2. В настройках и API — **годовая** (%); в расчётах по месяцам — переводить в месячную **только** через `(1 + r/100)^(1/12) - 1` (getMonthlyInflation).
3. Ввести хелперы по месяцу и множителю за N месяцев; везде использовать их и убрать линейное деление годовой на 12 для инфляции.
4. Обратная совместимость: если матрицы нет или ranges пустой — одна ставка `inflation_rate_year` на все месяцы.
