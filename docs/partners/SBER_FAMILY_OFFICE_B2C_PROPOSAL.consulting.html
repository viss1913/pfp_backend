Фаза 2 — SberID и финансовый профиль рекомендуем

Не реализовано в текущем демо. Целевая «идеальная система»:

  1. Кнопка «Войти через Сбер ID» (OAuth 2.0 / OpenID Connect).
  2. Экран согласия на scope (доходы, категории расходов, при необходимости остатки / ИПК — только по согласованию со Сбером).
  3. Адаптер данных → предзаполнение калькуляторов → клиент проверяет и правит.
  4. Fallback на ручной ввод, если отказ или недоступность API.
Клиент → FO → SberID (OIDC) → токены → Consent → API агрегатов Сбера → PFP (доходы/расходы) → отчёт → CTA

Postback/API продаж — отдельное ТЗ, не путать с SberID.

ИИ / GigaChat опционально

  • Подсказки агенту и клиенту, черновики пояснений; не замена инвестиционной рекомендации.
  • Рекомендуем GigaChat в изолированном контуре с ключами заказчика; отключение по флагу.
  • Все суммы в отчёте — из детерминированных расчётов, не из LLM.

ИБ и данные

  • Хранение данных пилота — РФ; TLS, JWT, разграничение по tenant.
  • Минимизация ПДн; согласие на обработку; при SberID — отдельный поток согласия и аудит доступа.
