# API Резолют: что должен вызывать ПФП (черновик требований)

**Направление:** исходящие вызовы **с бэкенда ПФП** на API **Резолют** (не наоборот).  
**Цель:** синхронизация каталога продуктов, опционально предкотировка, передача портфеля и получение данных для бесшовного перехода в UI Резолют.

Финальные URL, имена полей и коды ошибок — за вами; ниже зафиксирована **семантика** и **минимальный набор параметров**, который нам нужен для демо (этап 1: НСЖ).

---

## Общие требования


| Параметр        | Ожидание                                                                                                                                  |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Транспорт       | HTTPS                                                                                                                                     |
| Формат          | JSON, UTF-8                                                                                                                               |
| Аутентификация  | Согласовать: например `Authorization: Bearer <token>` или API-key в заголовке; отдельные ключи для демо/прод                              |
| Окружение       | Отдельный base URL для демо (sandbox), выдача тестовых учётных данных                                                                     |
| Идемпотентность | Для операции создания портфеля/заявлений — поддержка ключа идемпотентности (заголовок или поле тела), поведение при повторе — в ответе    |
| Ошибки          | Единая оболочка: HTTP-код, машиночитаемый `code`, человекочитаемое `message`, при 4xx/5xx по возможности детализация по позициям портфеля |


---

## Операция 1. Справочник связки продуктов (каталог для маппинга)

**Назначение:** ПФП подтягивает список продуктов, доступных для оформления через Резолют, и сопоставляет их с внутренними кодами ПФП.

**Вызов (логически):** `GET …/products` или `GET …/integration/products`

**Query (желательно):**


| Параметр        | Тип               | Обяз. | Описание                                  |
| --------------- | ----------------- | ----- | ----------------------------------------- |
| `active_only`   | boolean           | нет   | Если `true` — только актуальные к продаже |
| `updated_since` | string (ISO 8601) | нет   | Инкрементальная синхронизация             |


**Ответ 200 — элемент массива `items[]`:**


| Поле                      | Тип             | Обяз. | Описание                                                                                     |
| ------------------------- | --------------- | ----- | -------------------------------------------------------------------------------------------- |
| `resolut_product_code`    | string          | да    | Код продукта в Резолют (ключ для всех остальных вызовов)                                     |
| `pfp_product_code`        | string          | нет   | Если ведёте связку у себя — иначе маппинг только на стороне ПФП                              |
| `name`                    | string          | да    | Наименование для отображения                                                                 |
| `is_active`               | boolean         | да    | Признак актуальности                                                                         |
| `valid_from` / `valid_to` | string (date)   | нет   | Если актуальность задаётся датами                                                            |
| `product_kind`            | string          | нет   | Например `NSJ`, `DEPOSIT` — для маршрутизации на этапах                                      |
| `required_quote_params`   | array of string | нет   | Список имён обязательных полей для котировки/создания заявки по этому продукту (см. оп. 2–3) |

## Операция 2. Котировка по продукту (опционально для этапа 1)

**Назначение:** получить **официальные** цифры Резолют до или без сохранения заявления (если продуктовое решение — включить в MVP).

**Вызов:** `POST …/quotes` или `POST …/products/{resolut_product_code}/quote`

**Тело запроса — общая оболочка:**


| Поле                   | Тип    | Обяз. | Описание                                                                        |
| ---------------------- | ------ | ----- | ------------------------------------------------------------------------------- |
| `product_type`         | string | да    | Тип продукта в таксономии Резолют                                               |
| `resolut_product_code` | string | да    | Код из справочника                                                              |
| `parameters`           | object | да    | Набор параметров **диктует Резолют**; для НСЖ согласовать минимум (пример ниже) |
| `client`               | object | нет   | Обезличенно или минимально: возраст, пол — если влияет на тариф                 |


**Пример `parameters` для НСЖ (этап 1):**


| Поле              | Тип    | Описание                                   |
| ----------------- | ------ | ------------------------------------------ |
| `program_code`    | string | Код программы НСЖ                          |
| `term_years`      | number | Срок, лет                                  |
| `payment_pattern` | string | Порядок оплаты (код из вашего справочника) |
| `single_premium`  | number | нет                                        |
| `regular_premium` | number | нет                                        |
| `currency`        | string | нет                                        |


**Ответ 200:**


| Поле          | Тип               | Описание                                                  |
| ------------- | ----------------- | --------------------------------------------------------- |
| `quote_id`    | string            | Если котировка кэшируется и ссылается при создании заявки |
| `valid_until` | string (ISO 8601) | Срок жизни расчёта                                        |
| `currency`    | string            |                                                           |
| `amounts`     | object            | Суммы премии, покрытия и т.д. — структура по вашей модели |
| `breakdown`   | array             | Детализация по вашему формату (опционально)               |

## Операция 3. Приём портфеля (создание лица, заявлений, связь портфеля)

**Назначение:** передать из ПФП пакет позиций и данные лица; в Резолют создаются сущности для продолжения оформления в вашем UI.

**Вызов:** `POST …/portfolios` или `POST …/integration/portfolios`

**Заголовки (желательно):**


| Заголовок         | Описание                                                  |
| ----------------- | --------------------------------------------------------- |
| `Idempotency-Key` | UUID — повтор с тем же ключом не должен дублировать пакет |


**Тело запроса:**


| Поле        | Тип    | Обяз. | Описание                                          |
| ----------- | ------ | ----- | ------------------------------------------------- |
| `portfolio` | object | да    | Метаданные портфеля в ПФП                         |
| `person`    | object | да    | Данные страхователя/клиента (минимум согласовать) |
| `sales`     | object | да    | Блок продажи: агент, канал, коды партнёра         |
| `positions` | array  | да    | Список продуктовых позиций                        |


`**portfolio`:**


| Поле          | Тип               | Обяз. | Описание                          |
| ------------- | ----------------- | ----- | --------------------------------- |
| `external_id` | string            | да    | Устойчивый ID портфеля в ПФП      |
| `created_at`  | string (ISO 8601) | нет   | Момент формирования в ПФП         |
| `metadata`    | object            | нет   | Произвольные метки для отчётности |


`**person` (минимум на согласование):**


| Поле          | Тип           | Обяз. | Описание                           |
| ------------- | ------------- | ----- | ---------------------------------- |
| `last_name`   | string        | да    |                                    |
| `first_name`  | string        | да    |                                    |
| `middle_name` | string        | нет   |                                    |
| `birth_date`  | string (date) | да    |                                    |
| `gender`      | string        | нет   | Если нужно по продукту             |
| `phone`       | string        | нет   |                                    |
| `email`       | string        | нет   |                                    |
| `documents`   | array         | нет   | Тип, серия, номер — по вашей схеме |
| `address`     | object        | нет   | Структура по вашей схеме           |


`**sales`:**


| Поле                | Тип    | Обяз. | Описание                            |
| ------------------- | ------ | ----- | ----------------------------------- |
| `agent_code`        | string | нет   | Идентификатор агента в Резолют      |
| `agent_external_id` | string | нет   | ID агента в ПФП, если маппинг у вас |
| `channel_code`      | string | нет   | Канал продаж                        |
| `subagent_code`     | string | нет   | При необходимости                   |


**Элемент `positions[]`:**


| Поле                   | Тип    | Обяз. | Описание                                            |
| ---------------------- | ------ | ----- | --------------------------------------------------- |
| `resolut_product_code` | string | да    |                                                     |
| `parameters`           | object | да    | Тот же контракт, что для котировки (оп. 2)          |
| `quote_id`             | string | нет   | Если позиция привязана к ранее полученной котировке |


**Ответ 201 (или 200):**


| Поле                   | Тип               | Описание                                                 |
| ---------------------- | ----------------- | -------------------------------------------------------- |
| `portfolio_id`         | string            | ID портфеля в Резолют                                    |
| `person_id`            | string            | ID созданного/привязанного лица                          |
| `applications`         | array             | `{ "application_id", "resolut_product_code", "status" }` |
| `handoff`              | object            | Данные для перехода в UI                                 |
| `handoff.url`          | string            | Deep link в форму пакета/портфеля                        |
| `handoff.access_token` | string            | нет                                                      |
| `handoff.expires_at`   | string (ISO 8601) | нет                                                      |

## Операция 4. Бесшовный переход (может быть не REST)

Если вместо полей в ответе оп. 3 вы отдаёте отдельный endpoint выдачи ссылки/токена:

**Вызов:** например `POST …/handoff/sessions` с `portfolio_id` и подписью запроса.

Требование со стороны ПФП: в ответе — **готовый URL** или пара **token + base_url**, по которым агент/клиент открывает вашу форму уже в контексте созданного портфеля.

## Что просим утощить с Резолют на созвоне

1. Точные пути и версия API (`/api/v1/...`).
2. Обязательный состав `person` и `sales` для НСЖ на демо.
3. Поведение при частичном фейле `positions[]`.
4. Нужна ли оп. 2 в MVP или достаточно оп. 3 + отображение сумм только в UI Резолют.
