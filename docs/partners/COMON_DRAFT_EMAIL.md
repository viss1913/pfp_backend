# Черновик письма в Comon

Тема: Доступ к endpoint `recommended` для серверной интеграции

Здравствуйте!

Мы интегрируем данные Comon в наш финансовый сервис и хотим использовать публичный каталог рекомендованных стратегий для ежедневного обновления витрины в клиентском отчете.

Нас интересует именно endpoint:

`GET https://www.comon.ru/api/v2/strategies/?tags=recommended`

Сценарий использования:

- раз в сутки серверным запросом получать актуальный список `recommended`-стратегий;
- сохранять этот список в нашу внутреннюю БД;
- использовать сохраненные данные в отчетах и личном кабинете клиента;
- не выполнять высокочастотный парсинг и не обращаться к endpoint на каждый пользовательский просмотр.

Сейчас мы видим следующую проблему:

- при доступе с серверного контура (VPS в РФ) запросы к Comon блокируются;
- с серверной стороны мы получаем `403` / нестабильное поведение на уровне редиректов;
- при этом в браузере endpoint открывается корректно и возвращает JSON.

Просим подсказать, какой вариант интеграции корректен с вашей стороны:

1. Можно ли разрешить серверный доступ к этому endpoint по allowlist IP?
2. Есть ли официальный способ machine-to-machine доступа к каталогу стратегий?
3. Нужны ли специальные заголовки / токен / cookie / иной формат авторизации?
4. Допускается ли использование именно этого endpoint для ежедневной синхронизации 1 раз в сутки?

Если удобнее, мы готовы:

- передать наш серверный IP;
- ограничить частоту запросов;
- согласовать технический регламент обращения к endpoint.

Технический контекст:

- endpoint: `https://www.comon.ru/api/v2/strategies/?tags=recommended`
- ожидаемый формат: JSON с `paging` и `data[]`
- режим использования: 1 раз в сутки, без массового парсинга других страниц

Будем благодарны, если подскажете рекомендуемый способ стабильного доступа к этому каталогу.
