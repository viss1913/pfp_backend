Архитектура, размещение и состав платформы

Модульный монолит: один backend PFP API + ЛК клиента/менеджера. Два согласованных варианта размещения — пилот в облаке или полностью в периметре Сбера.

Вариант A

Облако BankFuture

Изолированный VPC · быстрый пилот

  • Yandex Cloud — отдельный tenant SBER (projectId 29)
  • Backend: Docker node:20-bookworm-slim + Chromium
  • MySQL managed · S3-совместимое хранилище (R2 / Object Storage)
  • FO Web UI — white-label, домен по согласованию
  • Данные пилота — РФ; egress по whitelist
Вариант B

Периметр Сбера

On-prem / private cloud · промышленный контур

  • Контейнеры Docker / Kubernetes в ДЦ банка
  • Backend + ЛК — в едином периметре доверия
  • MySQL или PostgreSQL — managed в контуре Сбера*
  • Объектное хранилище банка вместо внешнего R2
  • Корп. SMTP / шлюз уведомлений · GigaChat on-prem

* PostgreSQL — опциональная миграция с MySQL, отдельная оценка ИТ

Фаза 2 · Полная интеграция с экосистемой Сбер

После успешного пилота MVP — подключение к финансовым данным клиента и сопровождение портфеля в рамках согласованных стратегий. Не входит в текущий релиз · отдельное ТЗ с Сбером.

1 Sber ID + согласие Клиент даёт доступ к агрегатам счетов
→
2 Картина счетов Остатки: брокер, депозиты, карты, НПФ…
→
3 План vs факт Целевой портфель PFP vs реальные позиции
→
4 Ребаланс В рамках заданной стратегии и лимитов

Агрегаты по счетам фаза 2

  • Единая картина капитала клиента в ЛК и CRM менеджера
  • Меньше ручного ввода — актуальные остатки из контура Сбера
  • Триггеры для RM: отклонение от плана, срок ребаланса (как в CRM)

Авто-ребалансировка фаза 2 · vision

  • Стратегия задаётся в PFP: целевые доли, риск-профиль, горизонт
  • Система сравнивает план и факт, предлагает шаги
  • Авто-исполнение — только в согласованных рамках и с consent клиента
  • Исполнение сделок — через API брокера / каналы Сбера, не «в обход»

Что нужно от Сбера

  • API агрегатов: scopes, sandbox, тексты согласия
  • Модель поручений / рекомендаций (ИИР vs робо-advisory — юридика)
  • SSO менеджера, связка с CRM Private / Premier

Важно: на пилоте MVP — расчёт, отчёт и реферальные CTA. Ребалансировка в отчёте уже описывается как рекомендация; автоматическое исполнение — продукт фазы 2 после согласования модели с регуляторными требованиями.
