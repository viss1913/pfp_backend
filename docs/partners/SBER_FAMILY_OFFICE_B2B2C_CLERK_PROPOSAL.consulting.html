Family Office для бухгалтеров: канал Клерк.ру

Совместное предложение: бухгалтеры открывают свой family office под клиентов и получают комиссионный доход от продаж продуктов экосистемы Сбер через согласованную реферальную атрибуцию.

BankFuture PFP · Co-brand Клерк — на согласовании · 20 мая 2026 г.

Кратко

  • Канал: портал Клерк.ру (аудитория бухгалтеров) + агентский контур PFP.
  • Модель: бухгалтер = агент FO; клиенты бухгалтера → отчёт → CTA на продукты Сбера с partner_agent_id.
  • Для Сбера: тысячи доверенных консультантов без найма штатом; единый отчёт и дисклеймеры.
  • Co-brand: BankFuture × Клерк согласование
  • SberID: ускоряет onboarding клиента бухгалтера фаза 2

Ценность для Сбера

  • Дистрибуция через профессиональное сообщество бухгалтеров с репутацией и базой МСП/ИП.
  • Один отчёт Finam v2 под Сбер — без самодельных Excel и рисков формулировок.
  • Измеримые переходы: единый partner_agent_id бухгалтера на все продукты (НПФ, СК, УК, брокер).
  • Масштаб без прямого найма: Клерк привлекает агентов, BankFuture — платформа, Сбер — продукты.

Что уже готово у BankFuture

  • Агентский ЛК, регистрация агентов, CRM, субагентская сеть (при необходимости).
  • Тенант SBER (29), отчёт v2, витрина, трекинг ссылок в PDF.
  • Поле partner_agent_id — один ID бухгалтера на все четыре продукта Сбера.
  • Инфраструктура комиссий / partner_agent_id (см. agent network) — для учёта канала после согласования с Сбером.

Сценарий B2B2C (бухгалтер)

  1. Бухгалтер регистрируется в FO (через Клерк.ру — лендинг/приглашение, co-brand TBD).
  2. Заполняет partner_agent_id (ID, выданный Сбером или каналом — согласовать).
  3. Заводит карточки клиентов, цели, риск-профиль.
  4. Генерирует PDF/HTML-отчёт; все CTA содержат атрибуцию бухгалтера.
  5. Клиент переходит на оформление продукта Сбера; комиссия — по правилам тройного договора BankFuture / Клерк / Сбер.
Клерк.ру → [Бухгалтер-агент] → PFP (клиенты) → Отчёт → CTA + agent_id → Продукты Сбера

Техническое описание

Та же платформа PFP, что в B2C: Node.js, MySQL, PDF v2. Размещение — изолированный Yandex Cloud или on-prem Сбера. Для канала Клерк — отдельный landing URL и UTM utm_source=clerk (пример, финализировать в settings).

Интеграции

MVP сейчас

Реферальные ссылки в отчёте и письмах; без API продаж Сбера. Whitelist: npfsberbanka.ru, sberbank-insurance.ru, first-am.ru, sberbank.ru.

Клерк партнёр

  • Маркетинговое размещение и онбординг бухгалтеров — зона ответственности Клерк (согласовать с Сбером упоминание бренда Сбера).
  • Технически: deep link в FO, возможна SSO — отдельное ТЗ с Клерком.

SberID фаза 2

Клиент бухгалтера входит через Сбер ID → доходы/расходы без ручного опроса → быстрее до отчёта и CTA. Не блокирует запуск MVP.

ИИ / GigaChat

Подсказки бухгалтеру при заполнении анкеты клиента; черновики писем клиенту. Отключение по политике Сбера. Расчёты — без LLM.

ИБ

Агент видит только своих клиентов (tenant isolation). ПДн клиентов — оператор по договору (BankFuture / совместно). Клерк не получает полный доступ к ПДн без отдельного согласия.
