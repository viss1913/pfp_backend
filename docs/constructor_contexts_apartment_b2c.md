# B2C: цель «Квартира» — контексты для админки конструктора

На бэке уже сделано:

- Экстракция JSON: цель квартира → `goal_type_id: 4`, `name: "Квартира"`, `target_amount` = стоимость, `initial_capital` по цели, клиент — доход/пол/возраст как обычно.
- После экстракции сервер сам добавляет в `client.assets` актив **`type: "CASH"`**, `unlock_month: 0`, `current_value` = сумма «уже есть» (из `goals[].initial_capital` или, если модель положила только в `total_liquid_capital`, подставит в цель и пул). Так заполняется пул расчёта, как в API first-run.
- `term_months` для типа **3** и для **«Квартира»** выставляется **сервером** (те же правила, что для ПДС: пол + дата рождения).
- После firstRun в хвост генератору добавляются `other_goal_apartment_presentation_structure_ru` и `other_goal_apartment_narrative_hints_ru`.

Ниже — **классификатор на этапе сбора по квартире** (аналог `/INVESTMENT`) и **сценарий второго ИИ** (копипаст в `response` команды `/apartment`). Ключи подставь свои, если отличаются.

---

## 1. Классификатор (первый ИИ) — этап `/apartment`

Вставь в **classifier** команды, пока пользователь на сценарии квартиры:

```
Ты ИИ который определяет команды.
Сейчас клиент на этапе /apartment. Мы считаем накопление на квартиру.
Мы узнаём следующие параметры:
ориентир по стоимости квартиры (бюджет покупки)
первоначальный капитал, уже отложенный именно на квартиру
текущий месячный доход клиента

Если клиент ответил на все вопросы — напиши команду /firstRunAIB2C
Если клиент не ответил на все вопросы — напиши команду /apartment
```

## 2. Второй ИИ — сценарий `/apartment` (сбор трёх цифр)

Вставь в поле **response** команды `/apartment`:

```
Твоя задача — собрать три цифры, но не как опросник, а как естественную беседу:

На какую сумму смотришь по квартире (бюджет / ориентир по стоимости).
Сколько уже отложено именно на квартиру (если нет — ноль).
Текущий месячный доход (нужен для адекватной нагрузки на бюджет в расчёте).

Правила:
— Задавай вопросы по одному. Дождись ответа.
— Порядок можешь чуть гибко менять, если пользователь сам выдал цифры раньше — не переспрашивай то, что уже сказано.
— После каждого ответа — короткая реакция: кивок в духе «ясно», «окей», «принято», с лёгкой поддержкой или тёплой иронии.
— Добавляй эмодзи.
— Не обещай гарантированную доходность; говори «по модели расчёта», «прогноз», «оценка».
— Пол, возраст и имя из прошлых шагов не переспрашивай. Срок накопления в программе не спрашивай — его подставит расчёт.
```

## 3. Пример диалога и итоговый JSON (после экстракции + бэкенд)

**Диалог (фрагмент):** пользователь уже ранее дал пол и дату рождения.

- **Бот:** На какую сумму смотришь по квартире?
- **Клиент:** Ну миллионов двенадцать хочу.
- **Бот:** Ок 👍 А отдельно на квартиру уже что-то отложено?
- **Клиент:** Триста тысяч лежит.
- **Бот:** Принято. Доход в месяц до налогов какой ориентир?
- **Клиент:** Сто пятьдесят тысяч.

Допустим: **муж**, **1985-05-20** → срок как у ПДС **15 лет** → **term_months = 180** (подставит сервер).

**JSON (пример после обработки на бэке):**

```json
{
  "client": {
    "sex": "male",
    "birth_date": "1985-05-20",
    "avg_monthly_income": 150000,
    "total_liquid_capital": 300000
  },
  "goals": [
    {
      "goal_type_id": 4,
      "name": "Квартира",
      "target_amount": 12000000,
      "initial_capital": 300000,
      "term_months": 180,
      "risk_profile": "BALANCED"
    }
  ]
}
```

`monthly_replenishment` может отсутствовать — **OtherGoalCalculator** посчитает рекомендуемый взнос при расчёте.
