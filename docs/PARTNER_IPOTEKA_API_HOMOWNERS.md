# Партнёр Ipoteka API: расчёт + реферальная ссылка (страхование имущества / ипотека)

Сценарий: **только расчёт** у нас, потом **реферальная ссылка** на оформление на сайте партнёра.  
У клиента может быть ипотека — параметры ипотеки обязательны для расчёта.

Источник: [Redoc IpotekaAPI](https://ipoteka_backend-v2_general.ipoteka.test.fast-system.ru/redoc/index.html).

---

## 1. Как считается

1. **Справочники**  
   Один раз подтягиваем `GET /v2/dictionary` (банки, типы жилья, типы кредита, материалы, СК и т.д.) и маппим наши значения на их `id`/`code`.

2. **Создание экспресс-заявки = расчёт**  
   Шлём `POST /v2/express-applications` с телом `ExpressApplicationRequest`.  
   В ответе сразу приходит массив **расчётов по СК**: `data.calculations[]` — премия, комиссия, тарифы по рискам.

3. **Доп. расчёт по одной СК (опционально)**  
   Если нужно пересчитать только по одной компании:  
   `POST /v2/express-applications/{uuid}/calculate/{insurance_company_code}`.

4. **Реферальная ссылка на оформление**  
   - В ответах полной заявки (`POST/GET /v2/applications/{uuid}`) есть поле **`b2b_url`** — это и есть ссылка на оформление у партнёра.  
   - В примерах также фигурирует ссылка вида **`https://ipoteka.fast-system.ru/v2-app/{id}`** (где `id` — числовой id заявки).  
   Итого: после создания экспресс-заявки у нас есть `uuid` (и часто `id`). Реферальную ссылку либо отдают в ответе (например, при сохранении в полную заявку), либо собираем как `{baseUrl}/v2-app/{id}` — **уточнить у партнёра**.

## 2. Какие параметры нужны

Все обязательные для расчёта поля ниже. Ипотека учитывается: банк, сумма кредита, дата договора, ставка, тип кредита/жилья, льготная ипотека (ВТБ).

### 2.1. Обязательные общие

| Параметр | Тип | Описание |
|----------|-----|----------|
| `risks` | `string[]` | Риски: минимум `["real_estate"]`, можно добавить `"title"`, `"life"`. Для нашего homeOwners без жизни: `["real_estate"]` или `["real_estate","title"]`. |
| `city_address` | `object` | Адрес в формате DaData ([dadata.ru/api/suggest/address](https://dadata.ru/api/suggest/address)): `value`, `unrestricted_value`, `data` (postal_code, country, region, city, fias_id, kladr_id и т.д.). |

### 2.2. Ипотека (обязательно, если у клиента ипотека)

| Параметр | Тип | Описание |
|----------|-----|----------|
| `bank_id` | `integer` | ID банка из справочника `dictionary.banks` (не путать с `code`). |
| `mortgage_amount` | `number` | Сумма кредита (руб). |
| `mortgage_agreement_date` | `string` | Дата кредитного договора (например `"2024-01-01"`). |
| `interest_rate` | `number` | Процентная ставка по кредиту. |
| `credit_type` | `integer` | ID типа договора из справочника `creditTypes` (например «Новый полис»). |
| `housing_type` | `integer` | ID типа жилья из справочника `housingTypes` (первичка/вторичка и т.д.). |
| `is_mortgage_benefit` | `boolean` | Льготная ипотека (используется для ВТБ). |

### 2.3. Объект недвижимости (риск real_estate)

| Параметр | Тип | Описание |
|----------|-----|----------|
| `real_estate.build_features_type` | `integer` | Тип объекта из справочника `insuranceObjects` (например квартира). |
| `real_estate.floor_material_type` | `integer` | Материал перекрытий из справочника `interfloorMaterials`. |
| `real_estate.is_wooden_floors` | `boolean` | Деревянные перекрытия. |
| `real_estate.was_redesigned` | `boolean` | Была перепланировка. |
| `real_estate.is_agree_terms_declaration` | `boolean` | Согласие с условиями. |

При необходимости у них в полной заявке есть ещё: этаж, этажность, площадь, год постройки, кадастровый номер и т.д. — для экспресс-расчёта в примерах хватает указанных полей.

### 2.4. Добровольное страхование имущества (без ипотеки)

Когда у клиента **нет ипотеки** — только добровольное страхование квартиры/дома.

**У нас в системе (homeOwners)** параметры такие:

| Параметр | Тип | Описание |
|----------|-----|----------|
| `product_id` | `number` | ID продукта страхования имущества. |
| `object_params` | `object` | Характеристики объекта — пары «параметр : значение», по ним применяются множители из тарифов. Ключи: `wall_material` (brick / wood / blocks), `security` (alarm / none), `is_rented` (yes / no) и др. по продукту. |
| `limits` | `object` | Страховые суммы по блокам, руб: `constructive` (конструктив), `finish` (отделка), `property` (имущество), `civil` (граж. ответственность). |

Ипотечные поля не используются. Расчёт: базовая премия по лимитам и ставкам продукта × множители из тарифов по `object_params`.

**У партнёра (Ipoteka API)** экспресс-заявка в документации требует ипотечные поля (`bank_id`, `mortgage_amount`, `mortgage_agreement_date`, `interest_rate` и т.д.). Для чисто добровольного продукта (без ипотеки) нужно уточнить у них: либо эти поля опциональны и можно передать заглушки, либо есть отдельный метод/продукт только по имуществу. Параметры, которые относятся именно к объекту и риску «имущество», те же, что в п. 2.1 и 2.3:

- `risks`: `["real_estate"]` (при необходимости плюс `"title"`).
- `city_address`: адрес в формате DaData.
- `real_estate`: тип объекта, материал перекрытий, деревянные перекрытия, перепланировка, согласие с условиями.

Если партнёр подтвердит расчёт без ипотеки — достаточно этих блоков; ипотечные поля тогда не передаём или передаём по их правилам (например, нули/дефолты).

### 2.5. Риск «Жизнь» (опционально)

Если включаем `"life"` в `risks`, нужен массив **`insurers`** (страхователь/созаёмщики):  
`birthdate`, `is_male`, `is_borrower`, `part`, `declarative` (рост, вес, согласие), `extend` (профессия, спорт, здоровье и т.д.).  
Для сценария «только имущество + титул» массив можно не передавать или передать пустым (согласно описанию API).

## 3. Пример тела запроса (расчёт с ипотекой)

```json
{
  "risks": ["real_estate", "title"],
  "bank_id": 1,
  "mortgage_amount": 3200000,
  "mortgage_agreement_date": "2024-01-01",
  "interest_rate": 18.1,
  "credit_type": 682,
  "housing_type": 679,
  "is_mortgage_benefit": false,
  "real_estate": {
    "is_agree_terms_declaration": true,
    "build_features_type": 692,
    "floor_material_type": 701,
    "is_wooden_floors": false,
    "was_redesigned": false
  },
  "city_address": {
    "value": "г Москва",
    "unrestricted_value": "101000, г Москва",
    "data": {
      "postal_code": 101000,
      "country": "Россия",
      "region": "Москва",
      "city": "Москва",
      "fias_id": "0c5b2444-70a0-4932-980c-b4dc0d3f02b5",
      "kladr_id": 7700000000000
    }
  }
}
```

Все `id` (bank_id, credit_type, housing_type, build_features_type, floor_material_type) берутся из `GET /v2/dictionary`.

## 4. Ответ расчёта

В `data.calculations[]` по каждой СК приходит примерно:

- `insurance_company.code` — код СК (например `renis`, `absolut`);
- `total_insurance_premium` — суммарная премия;
- `client_reward` — вознаграждение клиенту/агенту;
- `tariffs[]` — по рискам: `risk`, `rate`, `insurance_premium`, `insured_sum`;
- `files[]` — ссылки на документы (письмо-заключение, заявление, черновик полиса) при необходимости.

Этого достаточно, чтобы показать клиенту расчёт и потом выдать реферальную ссылку.

---

## 5. Реферальная ссылка на оформление

- После `POST /v2/express-applications` сохраняем у себя **`data.uuid`** (и при наличии **`data.id`**).
- Варианты получения ссылки (уточнить у партнёра):
  1. В ответе полной заявки при сохранении/получении заявки по `uuid` приходит **`b2b_url`** — подставляем его как ссылку «Оформить на сайте партнёра».
  2. Если для экспресс-заявки дают только `uuid`/`id`, то ссылка может быть:  
     `https://ipoteka.fast-system.ru/v2-app/{data.id}` (или тестовый хост, который они укажут).

Дальше на их сайте клиент дооформляет, прикладывает документы и оплачивает.

---

## 6. Кратко для нашей интеграции (homeOwners)

- Нужно собирать с клиента (или из нашей анкеты):  
  **ипотека**: банк, сумма кредита, дата договора, ставка, тип кредита/жилья, льготная/не льготная;  
  **объект**: адрес (DaData), тип объекта, материал перекрытий, перепланировка;  
  **риски**: как минимум `real_estate`, при необходимости `title`.
- Один раз кешируем справочник `GET /v2/dictionary` и маппим наши справочники (банки, типы жилья, материалы) на их `id`.
- Вызов: `POST /v2/express-applications` → из ответа показываем расчёты по СК и сохраняем `uuid`/`id` для реферальной ссылки.
- Реферальная ссылка: либо `b2b_url` из полной заявки, либо `{baseUrl}/v2-app/{id}` — по договорённости с партнёром.

Если нужно, следующий шаг — описать маппинг наших полей homeOwners (object_params, limits, наличие ипотеки) в их `ExpressApplicationRequest` и накидать эндпоинт/сервис под это.
