# Задача: шаблоны отчётов для последующей интеграции на бэкенде

## Зачем это нужно

Команда бэкенда будет **генерировать PDF‑отчёты** по данным клиента (цели, портфель, расчёты). Нам нужны **готовые шаблоны** (вёрстка + понятная структура данных), чтобы дальше мы сами подставляли JSON с бэка и рендерили PDF у себя.

Ты **не подключаешься к нашему API** и не пишешь бэкенд — только готовишь то, с чем мы потом работаем.

---

## Что мы должны получить на выходе

### 1. HTML + CSS под печать (главное)

- Один или несколько файлов (по типам отчётов / типам целей), например:
  - `report-goal-default.html` + `report-goal-default.css`
- **Формат страницы:** A4, вертикальная ориентация, нормальные поля (например 15–20 мм), чтобы при печати/PDF ничего не обрезалось.
- Вёрстка должна быть **максимально предсказуемой для headless Chrome** (Puppeteer/Playwright): без обязательного интерактива, без сложного JS на странице. Если JS нужен только для превью в браузере — ок, но **итоговый вид для PDF** должен собираться из HTML+CSS (+ картинки).
- **Места под данные** — явно помечены, например:
  - плейсхолдеры `{{clientName}}`, `{{reportDate}}`, или
  - `data-field="clientName"` на элементах, или
  - комментарии в HTML `<!-- BLOCK: goal_summary -->` — главное, чтобы мы понимали, **куда что вставлять**.

### 2. Описание блоков (структура отчёта)

Отдельный файл **`REPORT_BLOCKS.md`** (или секция в этом же репо) со списком блоков **сверху вниз**, как в макете:

Для каждого блока указать:

| Блок | Тип | Описание | Откуда данные (имена полей) |
|------|-----|----------|-----------------------------|
| Пример: Шапка | header | Лого, название отчёта, ФИО, дата | `client.fullName`, `report.generatedAt`, … |

Типы блоков, которые нас интересуют: **шапка**, **текст**, **таблица**, **блок KPI/карточки**, **график** (см. ниже), **картинка**, **футер/дисклеймер**.

### 3. Пример данных (JSON)

Один файл **`report-sample-payload.json`** — **фейковый, но реалистичный** набор данных, которым можно **полностью заполнить** шаблон (все подставляемые поля и массивы для таблиц/графиков).

Цель: мы по этому JSON понимаем **точный формат**, который потом отдаст бэк.

### 4. Графики

Один из вариантов (заранее договориться в описании блоков):

- **Вариант A:** в шаблоне — `<img>` с фиксированным размером; в JSON примере поле `chartCapitalUrl` или `chartCapitalBase64` — мы сами сгенерируем картинку на бэке/фронте и подставим.
- **Вариант B:** в описании блока указать **формат данных** для графика (например массив `{ "year": 2025, "value": 1200000 }[]`) — тогда бэк сам построит график при рендере.

Нужно явно написать, какой вариант выбран для каждого графика.

### 5. Статика

- Логотипы, иконки, фоновые картинки — **отдельная папка** `assets/` с понятными именами.
- Шрифты: либо **веб‑шрифты** (ссылки в CSS), либо файлы шрифтов в `assets/fonts/` + `@font-face` в CSS.

---

## Референс по дизайну

- Макет в Figma: ссылку даст заказчик / тимлид.
- Важно: **визуально близко к макету** (отступы, шрифты, цвета). Небольшие отличия из‑за PDF допустимы, но критичные элементы (шапка, таблицы, читаемость) — в приоритете.

---

## Чего делать не нужно

- Не нужен деплой, не нужна интеграция с нашим Node‑сервером.
- Не обязательно React/Vue — **чистый HTML+CSS** для PDF предпочтительнее; если делаешь в React — приложи **собранный статический HTML** экспортом или инструкцией «как получить один HTML файл».

---

## Критерии приёмки (чеклист)

- [ ] Есть HTML (+ CSS), страница A4, без «сломанной» вёрстки при печати из Chrome «Сохранить как PDF».
- [ ] Все динамические места перечислены в `REPORT_BLOCKS.md` с именами полей.
- [ ] Есть `report-sample-payload.json`, которым можно мысленно (или скриптом) заполнить шаблон.
- [ ] Графики: для каждого указано — картинка с бэка или формат массива данных.
- [ ] Папка `assets/` + рабочие пути в HTML/CSS (относительные от папки шаблона).
- [ ] Короткий **README**: как открыть шаблон локально, как проверить печать в PDF.

---

## Срок и вопросы

- Срок согласовать с тимлидом.
- Вопросы по данным — писать в чат; если поля неизвестны, в `REPORT_BLOCKS.md` помечать **TODO** и предлагать разумные имена полей в JSON‑примере.

---

## Контакт

После сдачи: передать архив или PR с папкой вида:

```text
report-templates/
  README.md
  REPORT_BLOCKS.md
  report-sample-payload.json
  report-goal-default.html
  report-goal-default.css
  assets/
    ...
```

Дальше бэкенд забирает это и внедряет подстановку данных и генерацию PDF.
