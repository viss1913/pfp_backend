# Finam Report v2: хвостовые блоки

Документ фиксирует состав новых template-driven блоков `src/reports/finam_v2/`.
PDF/API подключаются через production composer `src/reports/finam_v2/buildFinamReportV2HtmlPackage.js`
при **`system_settings.report_finam = 2`** или эквивалентном включении через env **`FINAM_REPORT_VERSION`** (см. `src/reports/finam/reportVersionResolver.js`; без `FINAM_REPORT_VERSION_PROJECT_IDS` при заданной версии — по умолчанию только проект **14**). Во всех остальных случаях — текущий v1.

Production v2 берёт визуал из `page-*-v2.html`: `finamV2PageManifest.js` задаёт порядок, `finamV2TemplateLoader.js` читает шаблоны и инлайнит ассеты, `finamV2TemplateAppliers.js` подставляет реальные данные клиента, `finamV2PageComposer.js` отдаёт физические A4-листы в `pageHtmlList`. `toc` остаётся логическим оглавлением секций, но `page_start` и `page_count` считаются по фактическим `article.finam-v2-page`.

## Правило изоляции

- v1-шаблоны в `src/reports/finam/**` используются только как контент-референс.
- В v2 не переносим v1-клетку, классы `.page`, `.speech` и PDF-инъекции v1.
- Каждый лист внутри файла — отдельный `article.finam-v2-page` размером `595px × 842px`.
- Длинные блоки делятся на несколько листов, а не ужимаются мелким шрифтом.
- Для v2 PDF не применять v1 `injectReportPdfPageFillA4` и общий DejaVu font override, чтобы не ломать шаблонный визуал.

## Production-подстановки хвоста

`finamV2TemplateAppliers.js` заменяет демо-контент хвостовых шаблонов перед отдачей в PDF/API:

- `page-tax-planning-v2.html` берёт `overall_plan.tax_benefits` (`pds_benefits`, `iis_benefits`, `nsj_benefits`, `children_benefits`, `totals`) и строит KPI, таблицу льгот и график эффекта капитала с/без вычетов и софинансирования.
- `page-comon-autofollow-v2.html` берёт `report.comon_showcase.items[]` и `report.comon_showcase.disclaimer_ru`; если витрина не передана, выводит честный no-data блок вместо моковых стратегий.
- `page-idu-strategies-v2.html` использует локальный каталог `FINAM_V2_IDU_STRATEGIES` в `finamV2TemplateAppliers.js`, синхронизированный с `FINAM_IDU_STRATEGIES_CATALOG` в `buildFinamReportHtml.js` (v1); один `article` на лист.
- `page-inflation-v2.html` получает те же macro series, что v1: `cbr_key_rate`, `russia_cpi_inflation_yoy`, `moex_ofz_gcurve_2y`, `moex_ofz_gcurve_5y`, `moex_ofz_gcurve_10y`, `moex_rucbicp`. Если ряд пустой, показывается `н/д`, а не демо-цифра.
- `page-detailed-plan-v2.html` использует тот же расчёт строк пополнения/вычетов/софина, что v1 `buildRepleneshmentRows` в `buildFinamReportHtml.js`: полный `goals_detailed` передаётся в модель как `replenishmentReport`. Колонка **«Итоговый капитал»** считается отдельно: сумма `total_capital` из `monthly_schedule` только по целям **без** LIFE (и без RENT, как в первом цикле v1). **Весь горизонт** календаря попадает в отчёт; разбиение на PDF: **12 строк** на первой странице (hero), затем по **22 строки** на лист (паритет плотности с v1 по A4).
- `page-risk-declaration-v2.html` сохраняет юридический дисклеймер в конце: сначала берёт `riskDeclaration.legalNotes`, иначе использует fallback-текст про информационный характер, отсутствие ИИР, прошлую доходность и документы продуктов. Основной текст декларации сейчас статичен и одинаков для клиентов.

## Декларация о рисках

`page-risk-declaration-v2.html` теперь собирается как универсальная декларация о рисках по финансовому плану, а не как продуктовая карта экспозиции:

1. Вводная часть с объяснением, зачем клиенту нужна декларация и почему даже денежная форма капитала несёт риск.
2. Инфляционный риск.
3. Рыночный риск.
4. Риск повышенной волатильности и убытков по стратегиям автоследования.
5. Кредитный и корпоративный риск.
6. Риск ликвидности.
7. Регуляторный и налоговый риск.
8. Риски страховых продуктов.
9. Риск финансовой устойчивости финансовых организаций.
10. Риск несоответствия ожиданий.
11. Итоговое заключение про разумное управление рисками.

Текущая вёрстка группирует этот контент в **5 тематических A4-листов**:

- лист 1: вводная часть и инфляционный риск;
- лист 2: рыночный риск и волатильность автоследования;
- лист 3: кредитный, ликвидный и регуляторный контур;
- лист 4: риски страховых продуктов;
- лист 5: финансовая устойчивость организаций, риск ожиданий, итоговое заключение и юр. дисклеймер.

Юридический дисклеймер остаётся единственной production-подстановкой для этой страницы. Если лист начинает переполняться, сохраняем читаемость и тематическую группировку, а не возвращаем старые product exposure / matrix-блоки.

## Проверка

Локальный просмотр:

```bash
cd src/reports/finam_v2
python -m http.server 8766 --bind 127.0.0.1
```

Открыть: `http://127.0.0.1:8766/preview-merged.html`.

Скриншоты и A4-проверка:

```bash
node scripts/finam_v2_preview_screenshots.js
```

Скрипт должен падать, если страница вернула не `200`, не содержит `article.finam-v2-page` или любой лист имеет `scrollHeight > 842`.
