# Finam Report v2: хвостовые блоки

Документ фиксирует состав новых template-driven блоков `src/reports/finam_v2/`.
PDF/API подключаются через production composer `src/reports/finam_v2/buildFinamReportV2HtmlPackage.js`
при **`system_settings.report_finam = 2`** или эквивалентном включении через env **`FINAM_REPORT_VERSION`** (см. `src/reports/finam/reportVersionResolver.js`; без `FINAM_REPORT_VERSION_PROJECT_IDS` при заданной версии — по умолчанию только проект **14**). Во всех остальных случаях — текущий v1.

Production v2 берёт визуал из `page-*-v2.html`: `finamV2PageManifest.js` задаёт порядок, `finamV2TemplateLoader.js` читает шаблоны и инлайнит ассеты, `finamV2TemplateAppliers.js` подставляет реальные данные клиента, `finamV2PageComposer.js` отдаёт физические A4-листы в `pageHtmlList`. `toc` остаётся логическим оглавлением секций, но `page_start` и `page_count` считаются по фактическим `article.finam-v2-page`.

## Правило изоляции

- v1-шаблоны в `src/reports/finam/**` используются только как контент-референс.
- В v2 не переносим v1-клетку, классы `.page`, `.speech` и PDF-инъекции v1.
- Каждый лист внутри файла — отдельный `article.finam-v2-page` размером `595px × 842px`.
- Длинные блоки делятся на несколько листов, а не ужимаются мелким шрифтом.
- Для v2 PDF не применять v1 `injectReportPdfPageFillA4` и общий DejaVu font override, чтобы не ломать шаблонный визуал.

## Декларация о рисках

`page-risk-declaration-v2.html` больше не должен быть полупустой юридической памяткой. Целевая логика — персональная декларация о рисках по фактическим продуктам финансового плана:

1. Сводка по рискам: общий остаточный риск, ключевые риски, вывод для клиента.
2. Карта продуктовой экспозиции: продукт → компания/контур → роль → материальный риск.
3. Матрица `Риск / Доходность`: депозит/накопительный счёт, ПДС, ДУ, облигации, автоследование, акции.
4. Продуктовый риск: ПДС НПФ Ренессанс, депозит/накопительный счёт, ДУ Финам, автоследование Финам/Comon.
5. Протокол контроля: календарь контроля, триггеры пересмотра, юридические оговорки и связка с 5 рисками v1.

Обязательный продуктовый состав текущего прототипа:

- `ПДС НПФ Ренессанс`
- `Депозит / накопительный счёт`
- `ДУ Финам`
- `Автоследование Финам / Comon`
- `Облигации`
- `Акции` без привязки к конкретным бумагам

Страхование жизни (`LIFE`) в текущую декларацию о рисках не включать: оно остаётся отдельной goal-страницей, но не участвует в матрице `Риск / Доходность`.

Текущая раскладка матрицы `Риск / Доходность`:

- низкий риск / низкая доходность: `Депозит`, `Накопительный счёт`;
- низкий риск / средняя доходность: `ПДС`;
- средний риск / средняя доходность: `ДУ`, `Облигации`;
- средний риск / высокая доходность: `Автоследование`;
- высокий риск / высокая доходность: `Акции`.

Каждый риск-лист должен использовать свободную площадь под полезные управленческие блоки:

- экспозиция;
- влияние на цели;
- остаточный риск;
- что контролируем;
- триггеры пересмотра;
- короткий вывод для клиента.

Если лист получается полупустым, сначала объединяем близкие риски в один плотный one-pager. Например, облигации раскрываем одним блоком с подрисками `ставка`, `кредит`, `ликвидность`, а не отдельными пустыми листами.

## Проверка

Локальный просмотр:

```bash
cd src/reports/finam_v2
python -m http.server 8766 --bind 127.0.0.1
```

Открыть: `http://127.0.0.1:8766/preview-merged.html`.

Скриншоты и A4-проверка:

```bash
node scripts/finam_v2_preview_screenshots.js
```

Скрипт должен падать, если страница вернула не `200`, не содержит `article.finam-v2-page` или любой лист имеет `scrollHeight > 842`.
