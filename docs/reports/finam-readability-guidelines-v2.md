# Finam PDF Readability Guidelines v2

Применяется к контентным страницам отчета в `src/reports/finam/`.

## 1. Принцип страницы

Каждая страница должна отвечать на три вопроса клиента:

1. Что происходит?
2. Это хорошо или плохо для меня?
3. Что я делаю дальше?

Если блок не помогает ответить на один из этих вопросов, блок сокращается или переносится в приложение.

## 2. Формат подачи (обязательно)

- Суть (1 короткий абзац)
- Ключевые цифры (3-5 метрик)
- Интерпретация (2-3 буллета)
- Действия (2-4 шага)

## 3. Лимиты на текст

- Абзац: максимум 2-3 строки.
- Одна карточка = одна смысловая единица.
- Запрещено дублировать длинные дисклеймеры внутри каждой карточки.
- Юридические формулировки оставлять в колонтитуле или отдельном завершающем блоке.

## 4. Спецправила для проблемных зон

### 4.1 Риски

Использовать строгий шаблон:

1. Риск
2. Вероятность
3. Что контролируем
4. Остаточный риск

### 4.2 Стратегии/подборки

- Сначала критерии выбора.
- Затем карточки.
- Затем краткая оговорка по рискам.

### 4.3 План действий

Для каждого шага показывать:

- действие;
- эффект;
- ссылку/точку входа.

## 5. Чеклист перед выпуском PDF

- [ ] На каждой странице есть блок "что это значит" и "что делать".
- [ ] Нет абзацев длиннее 3 строк в ключевом контенте.
- [ ] Ключевые метрики визуально отделены от пояснений.
- [ ] Повторяющиеся служебные формулировки удалены из тела страниц.
- [ ] Риск-блоки соответствуют формату "риск -> вероятность -> контроль -> остаточный риск".
- [ ] Страница читается за 20-40 секунд без пояснений консультанта.

## 6. Быстрый тест качества

1. Тест "3 минуты":
   - читатель должен назвать текущее положение, приоритет и 2 следующих действия.
2. Тест "детальный разбор":
   - консультант не должен пересказывать страницу заново, только уточнять решения.
