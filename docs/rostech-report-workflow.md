# Ростех PDF: как работать с шаблонами

Короткая памятка для разработчика, который продолжает правки PDF-отчета Ростех.

## 1) Что правим

- Шаблоны страниц Ростех: `src/reports/themes/rostech/buildRostechPensionPagesHtml.js`.
- Прокидку данных в рендер: `src/services/reportPdfService.js`.
- Не трогаем другие темы/рендереры без отдельной задачи.

## 2) Источник данных

Для текста и графиков используем:

- `goal.summary` (основной источник),
- fallback: `overall_plan.tax_benefits.totals` (для `deduction_2026`, `cofinancing_2026`).

Важно: если в `goal.summary` приходит `0`, это не повод печатать ноль в PDF, если в `totals` есть значение.

## 3) Правила по текстам

- Год в строках про льготы: `текущий год + 1`.
- Налоговый вычет (`deduction_2026`) показывать с 2 знаками после запятой.
- Не удалять ключевые строки про софинансирование/вычет без явного запроса.

## 4) Как переносим дизайн из Figma

1. Берем точный `node-id` страницы.
2. Меняем только нужный экран (локально), не делаем массовую перестройку файла.
3. Сверяем:
   - структура блоков,
   - размеры шрифтов,
   - отступы между карточками,
   - цвета, рамки, графики.

## 5) Как тестим (обязательно)

1. Создаем/пересчитываем клиента через API `first-run` под агентским JWT.
2. Проверяем `GET /api/client/:id`:
   - `goals_summary.summary.tax_benefits_summary.totals`,
   - `goals_summary.goals[0].summary`.
3. Генерим PDF:
   - `node scripts/test_report_client.js <client_id>`.
4. Визуально сверяем с макетом.

## 6) Быстрая диагностика, если в PDF снова нули

- Проверить, что в JSON есть `totals.deduction_2026` и `totals.cofinancing_2026`.
- Проверить путь в коде: `overall_plan.tax_benefits.totals` (а не старый `overall_plan.summary...`).
- Проверить fallback-логику: нулевые значения должны переключаться на totals.

## 7) PR-чеклист (перед merge)

- [ ] Правки локальны: затронуты только файлы Ростех/PDF по задаче.
- [ ] В текстах и графиках используются реальные данные расчета (без хардкода сумм/лет).
- [ ] Для `deduction_2026` и `cofinancing_2026` работает fallback на `overall_plan.tax_benefits.totals`.
- [ ] Сгенерен свежий PDF (`scripts/test_report_client.js <client_id>`) и визуально сверен с макетом.
- [ ] В описании PR указаны `client_id` теста, путь к PDF и что именно проверено руками.
